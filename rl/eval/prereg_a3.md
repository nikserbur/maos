# Предрегистрация A3 — структурный RL (L2 + L3) и инвестиционный агент

> Зафиксировано **2026-10-23 до любого обучения** (агент A3). Изменения после измерения запаса допускаются только
> разделом «Поправки» с датой и причиной, ДО обучения; после начала обучения — никаких изменений протокола.
> Основания: PLAN-V2 §8–§9, приоритет владельца (RL обязан честно пройти гейт V5; гейт не ослабляется),
> METHODOLOGY-V2 §7.4, §10.2а; диагноз A2 §5.5–5.6 (выбор правила почти не управляет хвостом прибыли).

## 1. Гипотезы

- **H0 (запас, проверяется до обучения).** В семействе экземпляров с узким местом по мощности, жёсткими договорами
  и тесной кассой структурные ходы (сверхурочные, субподряд операций узкого места, альтернативные маршруты,
  дробление, инвестиции L3, финансирование, режим диспетчеризации) управляют ХВОСТОМ прибыли: лучшая неучащаяся
  структурная политика (выбор на валидации) значимо лучше лучшего статического правила по CVaR₀.₁(Π) на
  отложенных сценариях, и ex-post оракул по библиотеке политик показывает запас сверх лучшей эвристики.
- **H1 (RL, протокол §10.2а / гейт G1).** Обученная структурная политика лучше лучшего статического правила.
- **H2 (RL, замена чемпиона §7.4 / гейт G2 — главный).** Обученная политика лучше ЧЕМПИОНА — лучшей неучащейся
  политики, выбранной на валидации среди {лучшее правило, ключ CP-SAT, ключ ГА с тёплым стартом CP-SAT,
  «инвестируй, если окупается», сетка структурных эвристик}. Выигрыш, который даёт само пространство ходов, а не
  обучение, засчитывается чемпиону, а не RL.

## 4. Политики сравнения (все — на тех же сценариях)

1. **best_rule** — лучшее из 7 правил (EDD, SPT, LPT, CR, MWKR, MS, FIFO) по CVaR₀.₁(Π) на валидации, без ходов.
2. **CPSAT** — очередь по ключу CP-SAT (детерминированно, 60 с, подсказка — лучшее правило по F), без ходов.
3. **GA** — ГА «ключи по операциям» с тёплым стартом CP-SAT (8 сценариев seed 1000+, 30 с), без ходов.
4. **IIP («инвестируй, если окупается»)** — правило продукта: на валидации для каждого кандидата L3 на CRN считаются
   E[ЧДД], CVaR₀.₁(ЧДД), CVaR₀.₀₅(C_min), P(разрыва), дисконтированный срок окупаемости; кандидат покупается в неделю 0,
   если E[ЧДД] > 0, CVaR₀.₀₅(C_min) ≥ min(0, база) и нижняя граница 95 %-ДИ ΔE[Π] > 0; диспетчеризация — лучшее правило.
5. **H\*** — лучшая на валидации эвристика сетки `rl/eval/struct_policies.py:heuristic_grid` (пороги сверхурочных и
   субподряда по доле стоимости заказов с прогнозом просрочки, «срочный первым», буфер ликвидности, + IIP-покупки).
6. **champion** — лучшая из 1–5 по баллу валидации s = ΔCVaR₀.₁(Π)/V + 0.5·ΔCVaR₀.₀₅(C_min)/V к best_rule.
7. **oracle_bound** — ex-post максимум прибыли по библиотеке (сетка эвристик × {без/с IIP}) НА КАЖДОМ сценарии —
   недостижимая граница (не политика).
8. **RL** — по сиду: лучший по валидации чекпойнт (BC и PPO); кандидат гейта — сид с лучшим баллом валидации.

## 5. Метрики

Π — учётная прибыль после налога за 26 недель; C_min — минимум netCash (касса − просрочка платежей); запас
ликвидности — min(netCash + невыбранный лимит); P(разрыва); OTD; просрочка. Разности — **в % стоимости портфеля V**
(Σ цена × объём; устойчиво при E[Π] ≈ 0, A2 нормировал на |E[Π]|): ΔCVaR₀.₁(Π), ΔCVaR₀.₀₅(C_min), ΔE[Π]. По
экземплярам: IQM, парный бутстреп-ДИ 95 % (B = 2 000, seed 1), Уилкоксон; доля экземпляров с выигрышем.
Экстренное реагирование (стресс shock): Δ времени восстановления пропускной способности, Δ потерь прибыли и
минимума кассы от шока (шок − двойник), доля шоков, где политика лучше best_rule; ДИ — бутстреп по парам.
Интерпретация: доли ходов по видам, по режимам HMM и по типу эпохи (неделя / шок).

## 6. Гейт

- **G1 (§10.2а):** IQM ΔCVaR₀.₁(Π) к best_rule > 0, нижняя граница 95 %-ДИ > 0, **и** IQM ΔCVaR₀.₀₅(C_min) ≥ 0;
  стресс base — основной; остальные стрессы — отдельные утверждения.
- **G2 (§7.4, замена чемпиона — `gate_pass` в API):** то же к champion.
- RL считается прошедшим, если кандидат (сид, выбранный по валидации) проходит на holdout **и** IQM ΔCVaR₀.₁(Π)
  к той же базе > 0 у всех ≥ 3 сидов. Выигрыш вне ДИ не заявляется. Публикация ONNX и правило «RL» с ходами —
  только при G2.

## 7. Обучение (фиксируется до запуска)

Политика: MaskablePPO, MLP [256, 256], наблюдение 48, действия 13 (маски SimEnv). Эпоха = неделя или экстренное
событие, ≤ 3 хода за эпоху. Инициализация — BC (кросс-энтропия) по траекториям H\* каждого экземпляра на пуле
обучения. Награда — терминальная парная (CRN): 100·[(1+κ·1{Π_ref ≤ η})(Π − Π_ref) + 0.5·(min(0,C_min) −
min(0,C_min,ref))]/V, ref = H\* на том же сценарии, η — α-квантиль Π_ref экземпляра, α = 0.1, κ = 4 (CVaR-фокус).
Смесь стрессов обучения: половина сред — base, половина — shock. ≥ 1·10⁶ решений суммарно, 3 сида (1, 2, 3),
16 параллельных сред C++. Ранняя остановка и выбор чекпойнта — только по баллу валидации s к H\* (не holdout).

## 8. Правило остановки

Если H0 не подтверждается (лучшая эвристика не лучше best_rule на holdout ИЛИ ex-post оракул ≤ лучшей эвристики
по ΔCVaR в пределах шума), обучение не запускается; семейство исправляется поправкой (раздел 9) — это результат.

## 9. Поправки

**П1 (2026-10-23, до обучения; до измерения H0 на семействе).** Налог на прибыль в экземплярах A3 — нарастающим
итогом с начала года (`fin.tax_cumulative = true`, новый режим `CashWaterfall`, по умолчанию выключен — прежние волны
не меняются; ст. 285–287 НК РФ: база с начала года, авансы засчитываются). Причина: пилот на a3-m13 (валидация)
показал артефакт помесячных периодов с переносом убытка только вперёд — сверхурочные сократили просрочку на 600 ч и
подняли EBT, но налог вырос сильнее EBT (ранняя прибыль облагается, поздний убыток постоянных расходов пропадает):
модель наказывала более раннее завершение заказов. Тест: `CashWaterfall.A3CumulativeTaxEqualsRateTimesTotalEbtAndIdentitiesHold`.

**П2 (2026-10-23, там же).** Лимит линии калибруется по потребности в деньгах правила с наибольшей средней прибылью
из 7 на калибровочных сценариях (seed 4242), а не по EDD. Причина: в семействе EDD — очень слабое правило (SPT
лучше на 3–5 % V по CVaR), калибровка по EDD завышала лимит, и «тесная касса» не была тесной для лучшего правила.

Прозрачность: пилот (2 экземпляра, a3-s00 и a3-m13) прогнал неучащиеся политики на валидации и на holdout-сценариях
0–19; выбор политик по holdout не делался, обучение не начиналось. После П1–П2 генератор перезапущен; хэши ниже
заменяют хэши §2: `instances_a3.py` 3ef5675fa6e062eb, `index.json` d1683cf983301720, `SimEnvStruct.cpp`
c874a46e31af8f06, `CashWaterfall.cpp` 50523c2e8c3c7776, `scenarios.py` b64510538b89a024.

**П3 (2026-10-23, после H0, до PPO).** Наблюдение RL дополнено one-hot хода, который на том же наблюдении предложил
бы учитель H* экземпляра (61 = 48 + 13; учитель вычислим онлайн, развёртываемая политика = «H* + поправки RL»).
Причина: учитель различается по экземплярам (пороги, покупки), и без этого контекста BC физически не может его
воспроизвести — первый запуск (сид 1, только BC; PPO не обучался, holdout не трогался) дал согласие с H* 0.881 и балл
валидации −0.0059 к H*; кроме того, сглаживание меток распределяло массу на запрещённые маской ходы (исправлено:
сглаживание только по допустимым). Гейт, метрики, экземпляры, сценарии, награда, бюджет — без изменений.

**П4 (2026-10-23, ПОСЛЕ обучения варианта A — отдельный эксперимент, не замена протокола).** Диагноз A: все 3 сида PPO
сходятся (200 тыс. решений) к политике, совпадающей на валидации ПОБИТОВО с «H* + погашение кредитной линии излишком
кассы на каждой эпохе» (балл +0.01167 к H* у сидов 1–3 и у этой эвристики); дальнейшие отклонения валидацию только
ухудшают. Это выигрыш пространства ходов (ход repay доступен и одной строке правил), а не обучения. Поэтому:
(1) в V5 добавляется контроль «H*+sweep» и строгий чемпион champion+ = лучший на валидации из пула §4 п.6 ∪ {H*+sweep}
(пост-хок, помечается); (2) вариант B: учитель BC и база парной награды — H*+sweep, остальное как §7 (бюджет — 1 млн
решений на сид); гейт варианта B — к champion+. `gate_pass` в API — только если выигрыш RL держится против champion+.
Предрегистрированный G2 (к champion без «sweep») отчитывается как есть.
