### 1.2. `deriveState()` — состояние без бэкенда

`deriveInput.ts` описывает всё, что фронтенд уже знает: активный сценарий (`PriceScenario` с распределениями),
счётчики справочников, календарь, `optStore` (результат Стадии 2, время, форма), `planStore` (результат Стадии 1,
параметры), `KpiBundle`, прогноз. `deriveState.ts` (+ `deriveNodes.ts`, `derivePassports.ts`, `deriveValues.ts`)
строит `MethodMapState` с тем же контрактом, что будущий `GET /api/method-map/state`:

- **подблоки** — по правилам §3.4 честно: нет данных → `unconfigured`, НСИ/код → `default`, введено пользователем
  → `manual`, посчитано по сценариям → `estimated` (+ дата), портфель под другой сценарий или портфель пересчитан
  после плана → `stale` (с `reason`), мягкая ошибка бэкенда → `error`, не реализовано → `planned`;
- **параметры** — паспорт с живым значением (сценарий → `scenario.*`, форма «Оптимизации» → `opt.*`, «План» →
  `plan.*`), происхождение `manual`, если значение отошло от умолчания, `outOfRange` по разумному диапазону;
- **формулы** — `values[nodeId]` для `InfoTip` из последних ответов (`opt.cvar`: `cvar, alpha, n`; `plan.rule_score`:
  `rule, score, w_t, w_r, w_c`; `forecast.backtest` …) — 30 метрик из opt/plan/forecast;
- **блоки** — состояние = худшее из подблоков; бейдж — контекст первого реализованного подблока (имя сценария,
  портфель, станки…), вторая строка — что тянет блок вниз либо «рассчитано n · k в плане».

`useMethodMapState.ts` — хук для экрана и полосы: справочники кэшируются на уровне модуля (TTL 60 с,
`Promise.allSettled` — сбой одного эндпоинта не ломает остальное), активный сценарий =
`DecisionContext.scenarioId` → форма «Оптимизации» → последний портфель → первый в списке.

### 1.3. Экран `#/map[/<nodeId>]` — `MapScreen.tsx`, `MapCanvas.tsx`, `MapNodeView.tsx`, `MapEdges.tsx`, `NodePanel.tsx`, `PassportTable.tsx`, `MapList.tsx`, `map.css`

- **L0**: 8 блоков по фиксированной раскладке (`mapLayout.ts` — чистая геометрия: порты распределяются по стороне,
  чтобы пучок [1][2][3] → [6] не слипался; блоки разных рядов соединяются снизу/сверху; петля [4]→[4] — дуга над
  блоком). Рёбра — SVG с маркерами по виду: `data` сплошная, `feedback` пунктир (охра), `control` штрих-пунктир
  (ультрамарин), `explain` точки; `payload` — в подсказке; рёбра выбранного/наведённого узла подсвечены, остальные
  приглушены. Клик по ребру ведёт в узел-получатель.
- **Узел**: номер в моно и цвет блока (обводка слева, не заливка — A6), название caps, глиф состояния, бейдж и вторая
  строка, подвал «n подблоков · k в плане». `↓`/двойной клик разворачивает подблоки внутри контейнера (L1 без
  раскладки Sugiyama — см. §3).
- **Панель узла** (390 px, справа; < 1280 — поверх; < 960 — на всю ширину): хлебные крошки, вид узла, состояние +
  волна + «обновлено», причина, краткое «что это», **формула через `InfoTipContent`** (вынесена из `src/ui/InfoTip.tsx`,
  та же вёрстка) с живыми значениями последнего прогона, паспорт параметра (значение 24 px, единица меньше,
  происхождение caps, диапазон, «Изменить на экране»), таблица параметров (блок — агрегат, подблок — дети, формула —
  входы по рёбрам `param`), подблоки/содержимое, входы и выходы по рёбрам с переходом, мини-схема, «Открыть экран →»
  (контекст уносит `DecisionContext`), «Запустить» (ведёт на экран с действием), «Подробнее в Методике», «Спросить
  MENTAT» (отключено, волна 2).
- **Клавиатура и a11y** (§3.10): `role="application"` + `aria-roledescription`, узлы `role="button"` с
  `aria-describedby` (состояние · бейдж · причина), `Tab` по блокам, `→ ←` по рёбрам `data`, `↓ ↑` развернуть/
  свернуть, `Enter` панель, `Esc` закрыть, `1…8` фокус на блок, `/` поиск узла (по названию, id, metricId,
  paramId), `F` вписать, `?` подсказка клавиш (модал). Живой регион `aria-live="polite"` («Блок 2: по умолчанию ·
  задано 1 из 76»). Цвет не единственный сигнал — легенда глифов и видов рёбер внизу.
- **Пустые состояния** (§3.11): нет сценариев → подсказка «Создать сценарий →», нет справочников → «начните со
  Справочников», бэкенд недоступен → `ErrorBanner` с «Повторить», карта работает по последним ответам; чип
  «оценено по последним ответам» = `state.source === 'derived'`.
- **Адаптив** (§3.12): < 960 — вертикальный список блоков-аккордеон с теми же бейджами, рёбра текстом
  «→ в [4] (структурные ходы)».

### 1.4. Полоса, чипы, контекст, рельса — `src/ui/`, `src/shell/`

- `PipelineStrip.tsx` (+ `pipeline.css`): 8 ячеек по 36 px под верхней панелью на «Сценарии», «Портфель», «План»,
  «Мониторинг» (`ScreenDef.pipeline`); текущие блоки экрана подчёркнуты цветом блока; клик → `#/map/<block>`;
  < 1180 — без бейджей, < 820 — только номера и глифы. Монтируется в `AppShell` в своём `ErrorBoundary`.
- `BlockChip.tsx`: «[n] Название ↗» — в `ScreenHeader` (`blocks` prop; «Оптимизация»), в шапке «Плана», в боковой
  панели «Сценариев», в заголовке «Мониторинга».
- `src/shell/context.ts`: `DecisionContext` (`useSyncExternalStore` + `localStorage`): «Сценарии» пишут
  `scenarioId` при открытии сценария, «Оптимизация» — `scenarioId` при выборе и `portfolioRunId` после прогона
  (и читает `scenarioId` при старте), «План» — `planId`. `PlanScreen` теперь зеркалит параметры и результат в
  `planStore` (`planActions`), иначе карта не видела план.
- Рельса §2.3: группы `Модель / Условия / Решения / Наблюдение / Объяснение / Система` с подписями 9 px caps;
  экран `monitoring` = standalone `ForecastScreen` (раньше недостижим); `map` в «Объяснении» перед «Методикой»;
  `agents` — зарезервированный пункт в «Решениях» (приглушён, точечный маркер, подсказка «в разработке (волна 3)»),
  экран `src/features/agents/AgentsStub.tsx` — честное состояние в языке дизайн-системы (`EmptyState` со схемой
  `agent-layers`, 4 карточки «что появится и где», ссылки на узел [6] и RL в «Методике»). Стартовый экран — «Схема».
- Токены (`tokens.css`, §6.3): `--block-1…8` (только бейджи/обводки), `--state-*` → существующие `--status-*`,
  `--edge-*`, `--dur-flow`, `--pipeline-h`.

## 4. Отложено в G2 (и что нужно от бэкенда)

- **L1/L2 раскладкой Sugiyama** (`process-graph/layout.ts`): сейчас разворот блока — список подблоков внутри
  контейнера без рёбер между подблоками; детальные рёбра (`DETAIL_EDGES`) видны в панели как входы/выходы.
  Раскладка L1/L2 на канвасе и «сжатие остальных блоков до ярлыков» — G2.
- **Живой слой §3.7** (толщина рёбер по числу сценариев, split-бейджи A|B, оверлеи «состояние · значения ·
  свежесть»), **анимация прохода сценария §3.8**, экспорт SVG — G3 по плану.
- **Прогноз в состоянии**: `forecast` в `DeriveInput` поддержан (`mon.forecast`, `ext.prices`, `forecast.*`
  значения), но карта его не запрашивает (нет хранилища прогноза; `ForecastScreen` держит результат локально).
  Нужен `forecastStore` или `GET /api/method-map/state`.
- **MRP в [3]** — считается только внутри `PlanScreen` (локальный `mrp`), карте недоступен → `default`
  «считается при построении плана». Вынести в `planStore` в G2 вместе с мастером.
- **Хвосты длительностей и MTBF**: карта знает только счётчики (`operations`, `wcTypesWithMtbf`); индивидуальные
  `tail_weight/tail_index` по операциям потребуют `GET /api/operation_links` (есть в process-graph как предложение).
- **Паспорта с сервера**: `GET /api/params`, `PUT /api/params/:id`, `POST /api/params/:id/estimate` — до них
  провenance `manual/default` выводится по отличию от умолчания; `source/ci/validUntil` пустые.
- **Шаблоны сценариев** («Базовый», «Ценовой кризис», «Высокая ставка») — серверные (решение владельца);
  `PromptDialog` создаёт пустой сценарий и говорит об этом в подсказке.
- **Пресеты эвристик** — по-прежнему `localStorage` с пометкой в диалоге «локально» (нужен `heuristic_presets`).
- «Спросить MENTAT» — кнопка отключена до G4; командная палитра `Ctrl+K` глобально — G4 (на карте есть `/`).
- Lighthouse a11y — прогнать и зафиксировать число.
