## 2. Модули: что считается, что учтено, что оценено, in/out-of-sample, вердикт

Формат для каждого модуля: (1) формула как в коде и единицы; (2) потоки/ставки/время денег; (3) распределения и их идентификация; (4) in-sample vs out-of-sample; (5) вердикт против RJMF, приоритет, современная ссылка.

### 2.1 Стадия 2 — модель себестоимости (`Optimizer.cpp:174–236`)

1. Единичная себестоимость рекурсивно по `operation_inputs`: `c_p = [purchased]·base_cost·rawF + Σ_o [(t_o/60)(hourRate+laborRate) + setupCost/batch·[setupRequired] + cost_o]·riskInfl_o + Σ_in qty·c_in` (`:204–236`); часы на единицу `h_{p,w} = Σ_o (pertMean_o + setupTime_o/batch)/60` только по ведущему типу `primaryWct` (`:178–198`). Единицы: минуты → часы, ₽/ч.
2. Деньги: нет времени денег, нет закупочных отсрочек, НДС, энергия только через `hourRate` (если туда заложена), логистика отсутствует, ремонт отсутствует (в Стадии 2 нет поломок вообще). Амортизация, аренда, накладные — нет: «прибыль» = маржинальный вклад.
3. `riskInfl = 1.5` с вероятностью `riskCoef` (`:743`), один розыгрыш на операцию на сценарий для всего объёма (A2 #13 остаётся) — полностью систематический риск. `t_o` ~ логнормаль(PERT) + Парето-примесь (`:731–741`), та же, что в Стадии 1, но `hours_per_unit` для мощности использует `pertMean` без хвоста и переделки → Стадия 2 **систематически недорезервирует мощность** на ≈ tailWeight·E[min(8,F−1)] + riskCoef·0 ≈ 5 % при α=2.5, w=0.08 (хвост) — а Стадия 1 ещё добавляет +0.5·mean с вероятностью riskCoef (≈2.5 %). Это объясняет, зачем понадобился `stage1_feedback` (см. 2.9).
4. Всё in-sample (один набор `N` сценариев); OOS только для прибыли портфеля (2.6).
5. **Вердикт:** структурно верно, но это «вклад на покрытие», а не прибыль и тем более не денежный поток. **P0** для цели плана V2 (денежная позиция). Ссылка: Protopappa-Sieke & Seifert (2010), Buzacott & Zhang (2004) — себестоимость с оборотным капиталом и ценой денег.

### 2.2 Стадия 2 — распределения цен и копула (`Optimizer.cpp:238–287, 662–698, 745–768`)

1. `z_s = β_s·M + √(1−β_s²)·ε_s`, `π_s = F_s⁻¹(Φ(z_s))`; семейства: uniform, triangular, lognormal (точные), `t` — Корниш–Фишер при ν=5 (`:268–272`), `pareto` — симметричный Ломакс α=2.3 (`:274–278`), normal; жёсткий клип `[min,max]` (`:284–285`). Сырьё: логнормаль CV 0.20 с β=√corr + скачок p=0.06, α=2, кап 2.5 (`:759–766`).
2. Ставки/курс/инфляция в цены не входят. Горизонт не масштабирует σ (цена «за горизонт» = одна точка).
3. Ничего не оценивается по данным: `mean/stddev` задаёт пользователь, β по умолчанию √market_corr (0.5), `beta` в БД по умолчанию 0.7 (`schema.sql:246`), фолбэк CV 12 % (`:688`). Семейства не нормированы на одну σ (у Ломакса α=2.3 SD ≈ 2.26σ — A2 #12 остаётся). Клип создаёт точечные массы в хвостах → CVaR определяется значением `min_val`.
4. In-sample; второй набор для OOS тем же генератором (та же спецификация — проверяет только переобучение на сэмпле, не ошибку спецификации).
5. **Вердикт:** однофакторная гауссова копула допустима как базовая, но (а) параметры — «норматив/UI» без паспорта; (б) нет связи с макро; (в) несопоставимые семейства. **P0** (паспорт и обучение), **P1** (нормировка семейств, t-копула). Ссылки: McNeil, Frey & Embrechts (2015); RJMF Methodology §6 (эмпирические блоки вместо параметрических хвостов).

### 2.3 Стадия 2 — спрос и рынок (`Optimizer.cpp:791–814, 884–894`; `ExactCvar.cpp:172–180`)

1. `absorb_s = max(0, capM_s·demandMul − competitor_s)`, `capM = market_capacity` или `demand_max·1.2`; `mul_s(q) = clamp(1 + e_s·(1 − (C_s+q)/capM), 0.5, 1.3)`; `sold = min(q, absorb)`; `demand_max ← min(demand_max, absorb)` (`:810–814`). Годовые объёмы × `horizon/8640` (`:595`).
2. Спрос детерминирован; эластичность — наклон, не ε. Поскольку кандидаты и верхняя граница LP ≤ absorb, `fill ≤ 1` и `mul ≥ 1` всегда: ветвь «перепроизводство → падение цены» **недостижима** (A2 #14 остаётся; в точной LP тот же `upper = demand_max ≤ absorb`, `Optimizer.cpp:491`). Модель спроса фактически сводится к верхней границе и небольшому бонусу ≤1.3 за недогрузку рынка.
3. Не оценивается. `price_elasticity` по умолчанию 0.5 (`:106`).
4. —
5. **Вердикт:** «рыночная модель» декоративна. **P1**: стохастический спрос `E[min(q, D)]` с распределением, обученным по продажам/макро (Block [1]/[2] методологии). Ссылка: Lariviere & Porteus (2001); для макро-связи — RJMF §11 (перевод потоков в инновации).

### 2.4 Стадия 2 — кандидаты, критерии, отбор (`Optimizer.cpp:324–413, 816–972`)

1. Пул: 2 greedy + 5 water-filling + 5 mean-variance (λ∈{0.5,1,1.5,2.5,4}) + ×0.5/×0.7 копии + 80 случайных (`:833–875`) ≈ 120. Метрики: `metrics_of` — E, σ (/N), worst, VaR, CVaR = среднее ⌊αN⌋ худших (`:294–315`), регрет относительно пула (`:909–917`). Отбор: лучший `robust_score` среди `conc ≤ maxShare`, затем в полосе 3 % — самый «ровный» по загрузке (`:943–964`).
2. —
3. —
4. In-sample; OOS только для выбранного робастного (2.6).
5. **Вердикт:** после B2 (точная LP даёт +20–25 % по цели) пул кандидатов — лишь базовая линия; полоса 3 % и «ровность» — недокументированный второй критерий, меняющий ответ. **P1**: сделать LP основным путём, пул — отчётной базой; регрет — по пооборотному LP-оптимуму (Savage). Ссылки: Rockafellar & Uryasev (2000); Kim & Nelson (2006) для ранжирования с ДИ.

### 2.5 Стадия 2 — точная LP (`ExactCvar.cpp`)

1. `max η − (1/k)Σu_i`, `u_i ≥ η − P_i(x)`, `k = max(1,⌊αN⌋)` (`:360–361, 400–410`); `P_i(x) = Σ_s (price_{i,s}·ĝ_s(x_s) − cost_{i,s}·x_s)`, ĝ — вогнутая PWL (`:182–244`) с δ-оценкой сверху (`:321`); мощности `Σ h_{s,w} x_s ≤ Cap_w` (`:379–387`); доля ≤ maxShare по средним ценам (`:388–399`); масштабирование переменных σ_s и денег M (`:316, 324`); двойственные `−rowDual·M/capScale` (`:478`); округление до партий + жадный добор по истинной цели (`:98–158`).
2. Мощности без труда, без времени: одна точка-горизонт.
3. Те же сценарии, что эвристика (CRN) — корректно.
4. OOS: `evaluate_on(price2, cost2)` для LP и эталона эвристики (`Optimizer.cpp:530–531`). Нет ДИ, нет оценки разрыва оптимальности Мака–Мортона–Вуда.
5. **Вердикт:** лучший модуль стенда; соответствует RU-2000 буквально (вес 1/k вместо 1/(αN) — эквивалент эмпирическому CVaR при целом αN; при нецелом — смещение O(1/N), документировать). Замечания: (а) двойственные цены — цены ограничения **для CVaR-цели PWL-LP**, а не «точный сигнал ТОС» для имитационного завода (B2 §вывод завышает); (б) `kCapBoundSlack=1.05` (`:13`) — норматив; (в) без ДИ выигрыш «+22 %» — точечная оценка. **P1**: bootstrap-ДИ по сценариям (пересэмплирование строк `price/cost`), MMW-зазор. Ссылки: Rockafellar & Uryasev (2000, 2002); Mak, Morton & Wood (1999).

### 2.6 Стадия 2 — out-of-sample и диверсификация (`Optimizer.cpp:1062–1093, 399–413, 988–995`)

1. OOS: seed+9973, те же N; `gap = (ins − oos)/|ins|`, предупреждение при |gap_E| > 10 % (`:1082–1092`). HHI, концентрация по средним ценам (`:400–413`), вклад в риск `Cov/Var` (`:988–995`).
2. —
3. OOS генерируется тем же параметрическим генератором → проверяет оптимизационный сдвиг, но не адекватность модели (в RJMF holdout — те же обученные параметры, но независимо замороженный seed и запрет перенастройки; здесь `+9973` в коде — приемлемо, но стоит записать в паспорт).
4. Только робастный портфель; «цена робастности» = `E[x_exp] − E[x_rob]` при том, что `x_exp` не ограничен maxShare (`:952`) — смешивает неприятие риска и диверсификацию (A2 остаётся).
5. **Вердикт:** хорошо, но неполно. **P1**: OOS для всех сопоставляемых портфелей, ДИ, цена робастности при равных ограничениях.

### 2.7 Стадия 1 — развёртка, lot streaming, календари, рабочие (`Scheduler.cpp:273–342, 22–81, 228–244, 496–510`)

1. `sizeFactor = qty/batch`, `N = min(16, round(sizeFactor))` партий (`:292–295, 310–311`), `durMean = tExp·sizeFactor/N`, `σ·√(sizeFactor/N)` (`:325–328`); входы — партия k ждёт ⌈(k+1)L/N⌉−1 (`:335`). Календарь: `nextWork/advance` в минутах (`:28–50`), фонд `working_span` (`:54–65`). Рабочий — наименее занятый из допущенных (`:500–510`); фонд рабочего — общий календарь.
2. Стоимость труда: `laborCost = Σ busyByWorker·cost_per_hour` (`:1083–1085`), где `busyByWorker += work = dur + setup + downtime` (`:551, 568`) — **включает ремонт и ТО станка** (см. R1 в §3). Материалы — не в стоимости (`kpi.cost` — «без материалов», `kpiCatalog.ts:188`).
3. Длительности — см. 2.8. Сроки заказов без due — синтетика `horizon·(0.45+0.55(k+1)/n)` (`:695–696`), что делает демо-OTD артефактом (остаётся).
4. —
5. **Вердикт:** корректная полуактивная списочная схема (A2 #1: не «активное»; в `SCHEDULING.md §2` формулировка не исправлена). Потолок 16 партий и защита `jobs>4000 → N=1` (`:311`) — нормативы, влияющие на результат (и на ГА/RL: агент может их эксплуатировать — A4 §2.6). **P1**: документ, паспорт, тест чувствительности к потолку.

### 2.8 Стадия 1 — длительности, переделка, поломки/ТО (`Scheduler.cpp:344–354, 519–550`)

1. `d = LN(μ,σ_l)`; с вероятностью `tailWeight`: `d ×= 1 + min(8, F−1)`, `F = U^{−1/tailIndex}` (усечённый Парето); с вероятностью `riskCoef`: `d += 0.5·mean`; `d ≥ 0.1` мин (`:345–353`).
