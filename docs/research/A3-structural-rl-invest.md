## 2. Механика: структурные ходы и инвестиции

**Эпохи** — начало каждой недели и экстренное событие в момент наступления: отказ станка узкого места, прибытие срочного
заказа, вскрывшийся срыв поставки (будущее не раскрывается). ≤ 3 хода за эпоху; noop завершает эпоху; между эпохами L0
диспетчеризует в C++ статическим чемпионом (правило/ключ) или режимом, выбранным ходом.

| Ход | Механика в SimEnv | Стоимость / маска |
|---|---|---|
| `overtime` | суббота 06–22 у станков текущего узкого места до конца недели (+1 неделя вперёд максимум), календарь станков меняется, простаивающие переопрашиваются | 16 ч × ставка типа × 0.6 за станок-неделю [К] |
| `outsource_op` | джобы узкого места заказов с прогнозом просрочки, чьё ожидание в EDD-очереди > срока субподрядчика → джоба без станка (72 ч + работа), передаётся по готовности | 1.6 × (ставка + труд) × часы [К] |
| `alt_route` / `split` | ходы A1 (тип РЦ / техкарта / дробление) для самого срочного не начатого заказа | маски A1 |
| `invest0..2` | заказ кандидата: 30 % CAPEX + транш сейчас, 70 % + транш при вводе; ввод через lead: новый станок + рабочий-экипаж с допуском (`inv-<id>`), или модернизация (MTBF × 2, ремонт × 0.7); амортизация CAPEX/срок службы и ТО с недели ввода | ввод до конца горизонта; C + U ≥ транша |
| `draw` / `repay` | минимум выборки + 25 % невыбранного лимита / погашение 50 % излишка кассы над C_min | U > 0 / долг > 0 и C > C_min |
| `dispatch_*` | L0: чемпион / EDD / «срочный первым» поверх чемпиона | режим ≠ текущего; срочный — после прибытия |

**Прогноз просрочки** в наблюдении учитывает мощность: окончание заказа = max(цепочка по средним, очередь узкого места
по EDD / фонд станков). **Тождества водопада** с CAPEX-траншами держатся (`cash_residual` ≤ 10⁻⁶ масштаба, тест).

### 2.1 Оценка инвестпроекта (InvestEval, PLAN-V2 §9)
На каждом сценарии i — пара прогонов «база / проект» на одних и тех же случайных числах:
ЧДД_i = DF_H·Δ(C_H − D_H) + DF_H·[g_i·a(r_w, n_cont) + 0.7·остаточная стоимость·(1+r_w)^{−n_cont}],
g_i = [ΔΠ_i + (ΔDep + ΔInt)(1−τ_p)]/n_post — прирост операционного потока после налога в неделю использования,
продлённый на n_cont ≤ 260 недель («портфель повторяется», [К]); r_O = 18 % [НОРМ], r_w = (1+r_O)^{1/52} − 1.
**Применять**, если E[ЧДД] > 0, нижняя граница 95 %-ДИ E[ЧДД] > 0 на ОТЛОЖЕННЫХ сценариях и CVaR₀.₀₅(C_min) ≥ min(L, база), L = 0.
Тождества с `Finance.h`: −CAPEX + cf·a(r, n) = `finance::npv`, срок окупаемости — тот же алгоритм (тест на сетке r, n).

**Ручные случаи** (тест `InvestA3.MachinePaysOnlyWhenBottleneckBinds`, pytest `test_invest_eval_pays_when_bottleneck_binds`;
цех A×2 → B×1, заказы еженедельно, CAPEX 0.5 млн, 32 сценария):

| Случай | E[ЧДД] | 95 %-ДИ | ΔE[Π] за горизонт | P(разрыва) | окупаемость | вердикт |
|---|---|---|---|---|---|---|
| узкое место B перегружено (50 ед./нед.) | +0.40 млн | [+0.14; +0.84] | +0.07 млн | 0 | 32.8 мес | **внедрить** |
| без перегрузки (10 ед./нед.) | −0.61 млн | [−0.62; −0.59] | −0.07 млн | 0 | — | отклонить: E[ЧДД] ≤ 0, ДИ ≤ 0 |

**Семейство A3 (holdout-оценка IIP на валидации, 30 экз.)**: E[ЧДД] > 0 у 7 кандидатов из 90, нижняя граница ДИ > 0 у 5,
применить — у 2 (a3-m14, a3-l22: станок типа с наибольшей ценностью мощности по двойственным ценам). Отклонены в том числе
окупаемые станки на тесной кассе (a3-l21: E[ЧДД] +5.4 % V [+2.2; …], но P(разрыва) 0.56 → 0.81; a3-l27 +1.9 % V,
P(разрыва) 0.38 → 0.91) — **правило ликвидности связывает**: ЧДД-положительный станок на тесной линии не внедряется.
Ввод через 6 недель делает станок бесполезным для малых портфелей (окно 3 нед.): ЧДД −13…−66 % V.

### 2.2 Продукт: «Инвестпроекты» (`POST /api/analytics/investment`, блок `crn`)
Портфель — открытые `demand_orders`; кандидаты — TOC-узкое место детерминированного плана, его модернизация, тип с
наибольшей двойственной ценой мощности (`exact.duals` прогона оптимизатора; нет → второй по загрузке) и запрошенный
`wc_type_id` (`source: user`); CAPEX — `machine_capex` или норматив [К]. Сценарии — обученный макро-генератор
(`MacroSampler`, ставка пути → проценты по траншам): набор A (seed) — выбор правила L0 и отбор, набор B (seed + 1) —
**вердикт**. Налог — нарастающим итогом (П1). Отключение: `"crn": false`. Пример на демо-БД (24 сценария/набор, под
нагрузкой 8.9 с): правило SPT; все 3 кандидата отклонены (E[ЧДД] < 0; демо-портфель в разрыве во всех сценариях).

**Поля для UI** (`InvestCrn.candidates[]`, на отложенном наборе): `cand{id, kind, wc_type, capex, lead_weeks, opex_weekly,
life_weeks, mtbf_mul, repair_mul, prepay_share, source}`, `npv_mean`, `npv_ci95`, `npv_cvar`, `p_npv_neg`, `d_profit_mean`,
`d_profit_ci95`, `d_profit_cvar`, `profit_cvar_base/profit_cvar`, `cash_min_cvar_base/cash_min_cvar`,
`liquidity_cvar_base/liquidity_cvar`, `liq_threshold`, `p_cash_gap`, `p_cash_gap_ci95`, `p_cash_gap_base`,
`cf_weekly_mean`, `payback_weeks`, `payback_months`, `weeks_used`, `cont_weeks`, `rate_owner`, **`apply`**, **`reasons[]`**,
`selection{npv_mean, npv_ci95, d_profit_mean, cash_min_cvar, p_cash_gap, apply}`; верхний уровень: `status, rule, rules,
n_scenarios, seed, holdout_seed, macro, duals_used, params, rule_of_apply, assumptions[], ms`. Кнопка «внедрить в план»
— ход `invest` в структурном режиме / `schedule_invest` (не подключена к UI — по заданию).

## 3. Предрегистрированное семейство (rl/eval/prereg_a3.md §2)

30 экземпляров (`seed 20261023`): малые (окно 3 нед., 553–1 235 джоб), средние (6 нед., 672–2 749), крупные (12 нед.,
1 536–4 155). Заказы добавляются, пока загрузка самого нагруженного типа за окно не станет ρ; объём заказа ограничен

делала прибыль нечувствительной), постоянные 30–50 % маржинального дохода, сроки «как при ρ = 1», договор 3 % + 2 %/нед.
(потолок 25 %), лимит линии от пиковой потребности в деньгах (тесная касса — медиана).

**Поправки до обучения**: П1 — налог на прибыль нарастающим итогом (помесячные периоды с переносом убытка только вперёд
наказывали раннее завершение: сверхурочные подняли EBT на 0.06 млн, а налог — на 0.74 млн; ст. 285–287 НК РФ);
П2 — калибровка лимита по лучшему правилу (EDD в семействе очень слаб). Пилот трогал holdout-сценарии 0–19 двух
экземпляров неучащимися политиками (раскрыто в П1–П2).

Лучшие правила (валидация): SPT 18, EDD 6, FIFO 5, CR 1. P(разрыва) у лучшего правила:
0–0.11 на обычной кассе, 0.02–0.94 на тесной.

## 7. Диагноз и следующий эксперимент

**Что подтвердилось.** (1) Постановка: в семействе с узким местом и договорами структурные ходы управляют хвостом (H0,
+0.47 % V с ДИ), адаптивный запас сверх лучшей эвристики есть (оракул +0.59 % V). (2) Инвестиционное правило отделяет
окупаемые станки от неокупаемых и учитывает ликвидность (2/90 применено; тесная касса блокирует ЧДД-положительные проекты).
(3) Экстренное реагирование структурными ходами измеримо: −253 ч просрочки и −0.71 млн ₽ потерь на шок к лучшему правилу.

**Что не подтвердилось — узкое место в обучении (B), не в постановке (A).** PPO на терминальной парной CRN-награде
находит то, что даёт положительную разность почти в каждом эпизоде (погашение линии), и не находит условных структурных
решений, хотя оракул показывает +0.59 % V: (а) сигнал условных ходов редкий и знакопеременный по экземплярам (вариант B
выигрывает на 4 и проигрывает на 2 из 30, ранняя остановка по 32 сценариям валидации не различает); (б) одна политика на
30 экземпляров с наблюдением, где узкое место — «текущий тип» без идентичности, не может знать, что на a3-l22 станок
окупается, а на a3-s09 — нет (это знает только CRN-оценка проекта, а не наблюдение); (в) финальные чекпойнты B на 1 млн
решений деградируют (−0.016) — оптимизация на хвостовом весе κ = 4 неустойчива без ограничения шага.

**Следующий эксперимент (рекомендация).**
1. Сделать базой гейта чемпиона с «подметанием кассы» (оно теперь в пуле — П4) и **дать RL признаки проекта**: E[ЧДД] и
   P(разрыва) кандидатов на текущем состоянии (InvestEval на 8 сценариях в эпохе — уже есть функция) и признаки
   «выигрыш сверхурочных/субподряда по прогнозу» (разность прогноза окончания с ходом и без) — RL выбирает по оценённым
   последствиям, а не по сырому состоянию.
2. Обучение по экземпляру-классу (кластер ρ × касса) или с идентификатором экземпляра в наблюдении + CVaR-взвешивание
   по ПАКЕТУ CRN-сценариев (Tamar 2015) вместо per-episode κ; доверительная область (KL-ограничение) против деградации.
3. Валидация ≥ 128 сценариев для ранней остановки (32 не различают ±0.3 % V на отдельном экземпляре).
4. Отдельно — L0 как ранжирование операций (A2 §5.6 п.2) не проверялось.
