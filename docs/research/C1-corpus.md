## 1. Локальные эталоны строгости (seed A) — самые важные записи

Это не «литература», а **стандарты оформления и доказательности**, которым MAOS-V2 обязан соответствовать. Ниже — извлечённые правила
(S1–S12) с точным местом в пакете RJMF и тем, чем они становятся в MAOS.

### 1.1 `[RJMF-Note]` Research_note.md — «Финансирование технологического инфраструктурного экспорта и границы его окупаемости»
Файл: `…/RJMF_package_20261021 (2)/research/Research_note.md` (626 строк; рукопись 21.10.2026; репозиторий проекта `nikserbur/export-inflation-lab`). `Л`. → [1][2][3][5][7]

- **S1. Паспорт параметров** (§2.4, табл. 1 «Происхождение ключевых параметров»): каждому числу присвоен статус
  *наблюдение / статистическая оценка / калибровка / нормативное допущение*; параметры, которые нельзя идентифицировать из доступных
  данных (CAPEX, КИУМ, PD/LGD, η, φ), прямо названы «раскрытыми сценарными входами», а не оценками. **В MAOS:** обязательная колонка
  «статус» в каждой таблице параметров V2; параметры без источника не выдаются за оценку (требование §6 плана). Сегодня это нарушено
  коэффициентами макро-ползунков «для заметности» (A2 §21).
- **S2. Общие случайные числа (CRN) и выборка** (§2.5, ф. 15): 50 000 ID с общими исходными случайными величинами для всех сравнений;
  парные разности считаются на общих ID; дисперсия Монте-Карло по стратам `Var = Σ w_m² s_m²/n_m`; отдельная проверочная выборка с
  заранее зарезервированным начальным состоянием ГСЧ; смена размера блока вычислений не меняет исходные СВ (проверяется отдельно).
  **В MAOS:** контракт SimEnv — «seed → ID сценария → все шоки» детерминированы и не зависят от порядка/числа потоков; holdout-сиды
  фиксируются до обучения RL.
- **S3. Три NPV и финансовый водопад** (§2.1, ф. 5–6; Methodology §4–5): потоки каждого участника (собственник/банк/фондирование)
  считаются по полному водопаду с фиксированным **порядком операций внутри квартала** (9 шагов: внешние взыскания → расчёт
  потенциальных потоков → проверка событий остановки → резервы → выдача/погашения → администрация/фондирование → излишки → терминальный
  возврат остатков); нет бесплатных вливаний («новых неограниченных взносов при нехватке ликвидности нет»). **В MAOS:** водопад кассы
  предприятия (выручка с отсрочкой → закупки → зарплата/ремонты/логистика → проценты/погашения → налоги → касса/линия) обязан иметь
  документированный порядок операций и ту же дисциплину «касса не уходит в минус без явного события».
- **S4. Тождественное разложение NPV** (Methodology §5): NPV участника = сумма PV статей − стоимость удержания резерва
  `Σ R_t (d_{t+1} − d_t)`; разложение — **тождество**, сверяемое с прямым расчётом. **В MAOS:** такое же тождество «ΔКасса = Σ потоков»
  как независимый тест F (невязка ≈ 1e-12, как у RJMF для балансов КПМ: 1,72·10⁻¹², отв. рецензенту № 6).
- **S5. Критерий участия — по ожиданию, не по исходу** (§2.5; ответ № 2): условие `E[NPV_j] ≥ 0` проверяется на отдельном пилоте при
  заранее объявленных требуемых доходностях; отбор сценариев по реализованной NPV запрещён (смещение отбором). **В MAOS:** CVaR/E-критерии
  считаются по всей выборке, включая «плохие» сценарии; RL оценивается на отложенных сидах без отбора.
- **S6. Обученный генератор макро-неопределённости** (§2.4, ф. 14; Methodology §6): признаки `z = [100·ln(1+π/100), i_key − π − 2,
  100·ln S − (a+b·m)]`; ridge-VAR(1) со штрафом из {0,01; 0,1; 1; 10} (выбор по хвосту обучающего отрезка) и спектральным радиусом ≤ 0,98
  (итог 0,948797); SVD остатков (порог 90 % энергии — остались все 3 компоненты); гауссов HMM с 1–3 режимами как **классификатор режима**;
  симуляция — **совместные эмпирические блоки остатков** внутри режима (блок {1;2;4;8} мес.; выбор — 2 режима, блок 4 мес.);
  Student-t (МП) и Hill — только диагностика хвостов; неограниченный Student — только квантильный стресс (у лог-переменных нет
  экспоненциальных моментов для `E[L]`). От траекторий вычитается **точное условное мат. ожидание в логарифмах** (центрирование
  не зависит от числа симуляций). **В MAOS:** прямой кандидат на порт в `rl/macro/` (агент M): та же цепочка VAR→SVD→HMM→блоки с теми
  же защитами (спектральный радиус, точное центрирование, конечный носитель, честная оговорка «будущие экстремумы не покрыты»).
- **S7. CRPS-валидация выбора структуры** (§2.4, ф. после 14): число режимов (1–3) и длина блока (1/2/4/8) выбираются по совместному
  стандартизованному **CRPS на 24 перекрывающихся целях 2021–2022** при обучении до декабря 2019; затем переобучение на всей истории.
  Оговорка авторов: «короткая и перекрывающаяся валидация ограничивает точность выбора». **В MAOS:** [7] — тот же протокол
  rolling-origin для выбора структуры генератора цен/спроса; CRPS, а не только RMSE.
- **S8. Сравнение с наивными и ретроспективность** (§3.3): RMSE ARc(12 мес.) = 2,3473 п.п. против AR0 3,3677, «константа 4 %» 4,1550,
  «последний ИПЦ» 3,4899; прямо сказано, что сравнение ретроспективно (семейство выбиралось после знания ошибок), на актуализированной,
  а не «реальновременной» истории. **В MAOS:** бэктест прогноза цен всегда с наивной базой и с явной пометкой «ретроспективный».
- **S9. Структурная неопределённость отдельно от MC-ошибки** (§2.5; ответ № 4): 9 калибровок КПМ ↔ 13 схем весов × 5 значений λ =
  2340 строк; «равные веса» ≠ вероятности моделей. **В MAOS:** при нескольких сценарных ядрах (режимы, версии макро-генератора) —
  вес-схемы и «исключение по одной»; MC-ДИ и структурный разброс публикуются раздельно.
- **S10. Граничная постановка вместо точечного обещания** (§2.6, ф. 16–18; Methodology §15): цена потери `λ_π` — нормативная
  (сетка 0; 0,01; 0,1; 1; 10), задача `E[G] − λ(2A₁k + A₂k²) = 0` решается **со всеми корнями и вырожденными случаями** (нет корня —
  возвращается «нет решения», а не вымышленный порог). **В MAOS:** «цена ликвидности» и «цена робастности» — тот же жанр: граница
  `ΔE[прибыль] при ограничении P(касса<0) ≤ ε`, с кривой по ε и явными вырождениями.
- **S11. Явные границы результата** (§4–5): результат «условен на периметр, риск, дополнительные проекты и нормативные цены»; «строгая
  гипотеза Δπ ≤ 0 не выполнена ни в одном из 50 000 исходов, но верхняя 95 % граница частоты равна 0,1382 % — при нуле успехов верхняя
  граница не нуль» (Bonferroni по стратам); сценарные результаты, описательные зависимости и причинные эффекты разграничены (ответ № 29);
  RL упомянут только как будущее с условием «заранее определённая функция цели, ограничения, отдельная внешняя проверка» (§4).
  **В MAOS:** шаблон раздела «Границы» в каждом отчёте (`B2`-стиль + оговорки).
- **S12. Воспроизводимость** (Methodology §19–22; README пакета): SHA256-манифест, единый драйвер этапов (подготовка → обучение →
  дизайн → основной расчёт → проверочная выборка → отчёт), версии научного ядра в манифестах расчётов, «нерешённые состояния не удаляются
  из выборки», Python 3.12.14; независимые проверки формулами: 126 / 75 / 23 / 103 PASS.
