### 1.2 — результат плана (композиция X1 §5.1)

- **TOC** липнет к верху скролл-контейнера `.plan` (`top: −space-6`, непрозрачный `--bg-app`, hairline снизу), `scroll-margin-top` секций 48 px. Больше не плавает посреди KPI.
- **Результат переживает F5 и повторный вход**: `planStore` кэширует последние 3 ответа `/api/schedule` в `localStorage` (`readPlanCache`/`writePlanCache`, ужимается при квоте), `hydrate()` на входе в экран, `openCached(id)` — клик по строке истории. Шапка помечает `○ из кэша`. Бэкенд хранит только KPI (`kpi_series`), полного ответа по `plan_id` нет — см. §3.
- **KPI в ярусах**: ярус A — три плитки (`E[Cmax]` + полоса хвоста, `OTD` с метром, `CFaR` кассы или честная заглушка «к расчёту кассы ↓»); ярус C — `KpiTable`: 12 показателей свёрнутой таблицей «показатель · значение · контекст» (просрочка, загрузка с `FundBar`, переналадки, готовность, темп, задел, поток, ожидание, себестоимость, труд, ТО/ремонты, простой+календарь). Все «i» сохранены.
- **Узкое место — одна строка** (`BottleneckBanner`): ▲ · тип РЦ · % фонда · пик очереди · «почему → карта» · «методика ↗». Чипы переналадок/ТО/поломок/простоя — в таблицу яруса C.
- **ГА свёрнут в «Что определило»**: строка «ГА принят · +x % к F вне выборки · правило CR [детали]» раскрывает прежний `GaImproverCard` (кривая сходимости, формула ключа).
- **Гант**: палитра ≤ 7 цветов по изделию + «прочее» штрихом (`buildPalette`, раньше `var(--chart-9…12)` не существовали); группировка **по цехам** (`group_name` типов РЦ из НСИ, `useShops`) / по типам РЦ; ось — **даты** от начала горизонта (`fmtTickDate`: «дд.мм» на сутках, «чч:00» внутри суток); легенда и подсказка — `GanttParts` (были мёртвым кодом); инструменты — `Icon` plus/minus/expand, без `＋ ⤢ ⭳`; сетка сплошная hairline. Drag&drop пинов и полноэкранный режим сохранены.
- **Правила и рабочие — свёрнутые таблицы** (`ResultTables`): сортировка кликом по заголовку (`aria-sort`), выбранное правило — фоном и глифом ●, веса — чипами; рабочие — топ-12 по загрузке + «показать всех 80».
- **Касса**: бейджи — один `StatusChip` (цвет + глиф) вместо четырёх стилей; DSCR — «×» и «≫ 1,2× (ковенант)» при > 99; транши — подпись недели (1 · середина · N) и сумма первого транша.
- **Одна primary на экране**: «Рассчитать кассу» (на результате) или «Пересчитать с правками» (когда есть пины — касса становится secondary); «Новый план» — secondary с `Icon plus`; на пустом состоянии — «Начать: программа →».
- **Шапка `#/plan` в одну строку**: eyebrow «Решения · Стадия 1», «План #1f3ad4 · CR + ГА · дата», чипы блоков и одно действие; абзац-методология — только в пустом состоянии (со схемой `two-stages`). **История — свёрнутая секция после результата**, строка открывает прогон (`is-openable`, «открыть →» по hover), текущий — `is-chosen`.
- `LoadBars`: бар — `--chart-1` (статусный цвет больше не магнитуда), ≥ 85 % — только глиф ▲, значения в одну строку через `pct/hours`.

### 1.3 — мастер

- Заголовок шага — одна строка «Шаг N из 7 · Название · подсказка · [блок ↗]» (`wz-head` flex), на шаге «Результат» заголовка нет (TOC = заголовок). До первого поля шага «Программа»: шапка экрана 44 + 1 px + заголовок шага 32 + отступы ≈ **150 px** (цель ≤ 220).
- Футер: «← Назад · подсказка · к запуску → (quiet) · Далее → (secondary)»; **primary «Запустить» — только внутри шага 6**.
- `ProgramStep`: строка прогона — дата · сценарий · **E[Π] / CVaR / изделий** · критерий · «выбран» (`useRunSummaries`: `GET /api/optimize/runs/:id`, в памяти только метрики, кэш модуля).
- `ConditionsStep`: карточка-сводка «Наследуется из портфеля → сценарий «Базовый»» + бейджи + легенда состояний, затем `DiffList` «Что наследуется в прогон» (генератор, режим, покрытие, ключевая ставка → ставка линии, инфляция с проверкой «месячная», волатильность, ρ) с владельцами; «изменить в «Сценарии» →». Простыня `ParamField lg` снята; устаревшие — свёрнуты.
- `ObjectiveStep`: формула F — `bindFormulaParts(getMetric('plan.objective_weights').formula)` (две строки: подстановка пресета/весов/α и F), та же, что в «i».

## 3. Отложено / замечания

1. **Полный результат прогона по `plan_id` с бэкенда** — `GET /api/simulation/results` возвращает `SimResults` (другая форма), ответ `/api/schedule` не сохраняется; строки истории старше кэша (3 прогона на машине) открываются только как KPI/сравнение. Нужен эндпоинт в бэкенде (вне зоны G3a) — тогда `planActions.openCached` заменяется на fetch.
2. **Small multiples Ганта по цехам** — сделана группировка с сворачиванием (как Linear/Height), не отдельные панели на цех: при 3 цехах и 950 операциях раздельные панели удлиняют страницу втрое.
3. `QueueChart`, `LoadTimeline`, `GaImproverCard` (кривая), `CashTiles` PoL — ждут chart-систему 1.1 (`src/ui/charts`); в них остались пунктирная сетка (QueueChart) и цветная подпись пика.
4. Подписи дорожек Ганта (`Ленточнопильный отрезной…`) усечены до 188 px с `title` — двухстрочные подписи дорожек потребуют высоты строки 26 → 36 px; оставлено.
5. Чипы блоков `[3][4][5]` в шапке плана дублируют подсветку полосы — оставлены как ссылки на карту (UX-V2 §2.6), можно снять в 2.1 при переходе на общий `ScreenHeader`.
6. `optimization/kit/StatusChip` импортируется в план напрямую (`CashTiles`) — до слияния китов в `src/ui/kit` (2.1).
