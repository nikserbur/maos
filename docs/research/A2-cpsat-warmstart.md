## 0. Итог в пяти строках

1. **Правило «CP-SAT»** работает в продукте через sidecar (`rl/cpsat_service.py`, 127.0.0.1:8091): полная модель
   (альтернативные станки, наладки circuit, рабочие cumulative, календари, лоты), старты/станки → пины,
   дальше неизменный МК/CVaR; недоступный sidecar → `error_soft`. Пины воспроизводят решение солвера побитово (тест).
2. **ГА с тёплым стартом CP-SAT** (режим «ключи по операциям» рядом со структурной хромосомой): на бенчмарках
   разрыв к BKS ГА **27,5 % → 0,01 %** (Taillard) и **25,4 % → 1,0 %** (Brandimarte) — но весь выигрыш даёт
   затравка: ГА не улучшает почти-оптимальный план CP-SAT. На обогащённых экземплярах MAOS (до 1 380 джоб,
   жёсткие сроки) CP-SAT за 60 с уступает структурному ГА на 6/12 (план 1: F 5 712 против 3 414 ч).
3. **«Цена детерминизма»** (жёсткий план CP-SAT против робастно донастроенного на тех же отложенных сценариях):
   в продукте на плане 3 — ΔE[Cmax] **−15,8 ч [−21,5; −9,8]**, ΔCVaR **−10,2 ч [−15,4; −5,7]**, Δпросрочка −19,7 ч;
   на стенде по 12 экземплярам — CVaR F жёсткого CP-SAT хуже лучшего правила на **+13,1 % [+4,4; +30,5]**.
4. **Обогащение НСИ** открыло ходы: на неделе 0 по 12 экземплярам доступны outsource 31, reroute 12,
   reassign 63 действий (в A1 — 0/0/0); 9/12 экземпляров имеют все три вида.
5. **RL (главный раздел §5): гейт НЕ пройден.** Реактивная постановка построена (шоки раскрываются онлайн,
   статические базы их не видят), L0 «выбор правила» с BC от чемпиона и PPO (4 варианта, 3 сида, 10,3 млн
   шагов). Валидация приняла BC (= статический чемпион) в 8/9 сидах; единственный принятый PPO-чекпойнт на
   отложенных: ΔCVaR₀.₁(Π) к лучшему правилу +0,0002 % [−0,0010; +0,0055] (p = 0,47); отвергнутые финальные PPO
   значимо хуже (−0,015 % [−0,037; −0,002]). Узкое место — **постановка (A)**: даже «ясновидящий» ex-post выбор
   лучшего статика на каждом сценарии даёт ΔCVaR₀.₁(Π) ≤ 0,01 % на 5/12 экземплярах — IQM-гейт по экземплярам
   недостижим перестановкой правил при этой экономике; деньги от реактивности есть в среднем и в потерях от шока
   (оракул «срочный первым»: −0,78 млн ₽ [−1,03; −0,56] на шок), но не в хвосте. Следующий эксперимент — §5.6.

## 2. Правило «CP-SAT» в продукте

### 2.1 Модель sidecar (`rl/bench/cpsat_full.py`)
Вход — джобы ТОЙ ЖЕ развёртки Expander, что у правил (индексы совпадают с `run_schedule`), станки, общий и
индивидуальные календари, число рабочих и матрица допусков, сроки заказов, подсказка (план лучшего правила по
F = Cmax + 0,5·Σпросрочки). Переменные и ограничения:

| Элемент | Модель |
|---|---|
| Альтернативные станки (FJSP) | необязательный интервал на пару (джоба, станок), `ExactlyOne`; длительность на типе — `dur_by_type` |
| Наладки при смене изделия | `AddCircuit` по станку: дуга i→j (литерал), σ_j = first_j + Σ_{изделие_i≠изделие_j} a_ij; интервал включает наладку (как `sim_place`). Если у станка > 60 кандидатов **[К]** `rl.cpsat.circuit_max` и есть наладки — джобы с альтернативами берут станок из подсказки (`routing = fixed_from_hint:N`); иначе консервативно σ = 1 |
| Рабочие | `AddCumulative`: общий (ёмкость = число рабочих) и по типу РЦ (ёмкость = допущенные); пересечение допусков между типами — релаксация, назначение рабочего делает `sim_place` |
| Календари | **единый календарь** (демо) — ось рабочего времени `Warp`: модель решается в рабочих минутах без перерывов и переводится обратно (`nextWork`/`advance` — точная семантика `sim_place`, операция «растягивается» через перерыв); **индивидуальные графики** — запрещённые интервалы в `NoOverlap` станка (операция целиком в смене; длиннее смены — средний коэффициент растяжения; 24×7 — без перерывов) |
| Лоты/подпартии/входы BOM | предшествование `preds` Expander без изменений |
| Запуск/поставки | `release`; поставка без станка — интервал фиксированной длины без ресурса |
| Критерий | Cmax + (0,5/w_time)·Σ просрочки заказов (та же структура, что F Стадии 1) **[НОРМ]** `rl.cpsat.w_tard` |
| Тёплый старт | `repair_hint`: план правила → целые длительности, наладки по смене изделия, окна, конкретный допущенный рабочий, старт не раньше подсказки → **полная** допустимая подсказка (CP-SAT: «hint is complete and feasible»); за лимит нет решения → исправленный план со статусом `HINT` (честно помечен) |
| Крупная модель | > 1 000 джоб **техн.** `rl.cpsat.large_jobs`: presolve без пробинга/симметрий (на полном демо-портфеле 2 808 джоб presolve съедал весь лимит, статус UNKNOWN) |

Не моделируются плановое ТО и поломки — их учитывает МК над пинами. Найдено и исправлено по ходу: (а) станок 24×7
в смешанных календарях падал на общий календарь; (б) запрет пересечения смен делал CP-SAT хуже правила на демо
(Cmax 3 094 против 2 753 ч) — заменён осью рабочего времени при едином календаре (2 723 ч); (в) консервативные
наладки на станках с сотнями кандидатов — исправлено фиксацией маршрута по подсказке (план 1: 1 063 → 934 ч);
(г) фиксация маршрута срабатывала и без наладок (Brandimarte: mk07 +52 %) — теперь только при наличии наладок.

### 2.2 Конвейер `run_schedule(rule="CP-SAT")`
`plan_cpsat` → подсказка (лучшее из 7 правил по F) → `build_payload` → `solve` (HTTP, таймаут = лимит + 30 с;
недоступен → `error_soft` с текстом «sidecar … не отвечает … Запуск: rl/.venv/bin/python -m rl.cpsat_service») →
`pins_from` (старт «не раньше» + станок; ручные пины важнее) → ключ = ранг старта → те же МК/CVaR, ГА, проверка
вне выборки. В таблице правил — 8 строк (CP-SAT выбран + 7 правил для сравнения). Ответ `cpsat`: `status, objective,
bound, time_s, setup_mode, calendar_mode, routing, from_hint, makespan_solver_h, makespan_replay_h, best_rule,
gap_to_rule` (детерм. Cmax воспроизведения к лучшему правилу), `gap_to_rule_score`, `price_of_determinism`.

**Пример (продукт, демо-план 3 после обогащения, 886 джоб, лимит 30 с, 200 сценариев, ГА 20 пок.) [Н]:** CP-SAT
FEASIBLE за 31,6 с; Cmax солвера 106,32 ч = воспроизведение пинами 106,30 ч; лучшее правило MS 107,87 ч
(`gap_to_rule` −1,4 %). Под Монте-Карло жёсткий план хуже MS по F (10 800 против 9 914): пины «не раньше»
не дают сдвинуть операции влево при удачных длительностях. ГА принят, победил структурный режим
(`seed_source: cpsat`, ключи по операциям тоже допустимы, но хуже на отложенных).

## 3. CP-SAT как тёплый старт ГА; V4; «цена детерминизма»

### 3.1 Два режима хромосомы
Структурная (5 весов нормированных критериев + сдвиги заказов, затравки — правила) и **ключи по операциям**
(ген = ключ джобы ∈ [0,1]; затравки — нормированные старты CP-SAT `s_i/max s` и нормированные ранги ключей
правил; при CP-SAT станки берутся из его решения, ГА ищет робастную очередность; σ₀ = 0,05, мутирует
≈ 20 генов **[К]** `rl.ga.opkey`). Оба режима — на обучающих сценариях [0, NS), принимается лучший по отложенным
[NS, NS+NV) из тех, что лучше базы и там, и там. `ga_mode=auto`: оба при CP-SAT, иначе прежний структурный
(поведение `auto`-расписания не изменено). Тесты: затравка из стартов CP-SAT воспроизводит его порядок и станки
при отсутствии возмущений; детерминизм по seed (`improver`, Ганта, `cpsat` побитово).

## 5. RL: реактивное управление под неопределённостью (приоритет владельца)

### 5.1 Постановка (A): события раскрываются онлайн, статические базы их не видят
- **Генератор событий базы** **[К]** `rl.shock.p_base`: на сценарий P(отказ узкого места) = 0,2, P(срочный заказ) = 0,3,
  P(срыв поставки критичного входа) = 0,2 (+ поломки, тяжёлые хвосты, макро-режимы HMM, дефолт покупателя — как в A1).
  Стресс **«шок»**: каждое из 4 событий с вероятностью 0,5 и ≥ 1 в каждом сценарии; четвёртое — переключение в
  кризисный макро-режим с недели U[2,10] (сплайс кризисного пути генератора). Поток `[seed, 913]` — CRN по индексу.
- **Механика в SimEnv** (времена — доли календарной нижней оценки Cmax экземпляра `max(цепочка, Σработа/станков типа)`):
  отказ — станок самого загруженного типа недоступен на окне, начатая операция прерывается до конца окна (ремонт
  оплачивается); срочный заказ — копия части заказа-образца (×1,3 к цене **[К]**), прибывает по ходу, жёсткий срок =
  прибытие + U(1,5; 3)·LB заказа в календарном времени, просрочка → потеря 50 % выручки **[К]** `rl.shock.rush_loss`;
  джобы срочного заказа идут ПОСЛЕ джоб плана, поэтому ключи ГА/CP-SAT не сдвигаются, а статический план ставит
  неизвестные ему джобы первыми по сроку (сильнейшая разумная реакция статики); срыв поставки — длительность
  «поставки» затронутых заказов растёт, раскрывается только по факту.
- **Наблюдение L0** (+4 признака, `obs_l0` 206 → 210): отказ активен; шок уже был; доля невыполненной срочной работы;
  поставка запаздывает (дольше ожидаемого). Будущее не раскрывается.
- **Базовые линии** считаются до исполнения по средним и только воспроизводятся: лучшее правило (7), статический
  чемпион (лучшее из 7 правил + очередь CP-SAT по CVaR₀.₁(Π) на **валидации**, seed 777), ключ ГА (8 сценариев seed 1000+),
  ключ CP-SAT (`rl/results/cpsat_keys_a2.json`, 60 с, 12/12 FEASIBLE).
- **Экстренное реагирование** — метрики на отложенных шоковых сценариях против CRN-двойника «без шока»: время
  восстановления пропускной способности (скользящее окно 72 ч ≥ 0,9 × до шока **[К]** `rl.shock.window`),
  просрочка и потеря прибыли/минимума кассы, приписываемые шоку (шок − двойник), доля шоков, где кандидат лучше
  лучшего правила.
- **Крючок `invest`** (A3): `EnvConfig.investEnabled=false` по умолчанию — действия не входят в пространство L2
  (размеры политик A1 не меняются); при включении — `kMaxWct` действий, маска требует `Instance.investCapex > 0`,
  ход пишется в журнал «крючок A3: мощность и транш не моделируются» (тест).

### 5.3 Обучение (B): BC от чемпиона → PPO с CVaR
- Действия L0RuleEnv: 0..6 — правило, 7 — очередь по ключу CP-SAT, 8 — статический чемпион экземпляра, 9 — «срочный
  первым» поверх чемпиона. Политика «всегда 8» совпадает с чемпионом побитово (тест на CRN), поэтому BC начинает
  РОВНО с чемпиона, а CP-SAT — тёплый старт там, где он чемпион (plan3, rnd7).
- **BC**: эпизоды чемпиона (6 стохастических + 1 детерминированный на экземпляр; ≈ 76 тыс. решений), кросс-энтропия к
  действию 8 со сглаживанием 0,3 (p(чемпион) ≈ 0,73 — разведка PPO) **[К]** `rl.l0rule.bc`.
- **PPO** (MaskablePPO, MLP [128,128], 16 сред): терминальная прибыль по Рокафеллару–Урясеву (1−λ)X + λ(η − (η−X)⁺/α),
  α = 0,1, λ = 0,5, η — α-квантиль последних эпизодов экземпляра **[К]** `rl.l0rule.cvar`. Обучение — на смеси
  генератора базы и стресса «шок» (по половине сред). Ранняя остановка — только по валидации (seed 777, 16/экз.),
  балл = средняя по экземплярам ΔCVaR₀.₁(Π)/|EΠ| к чемпиону + 0,5·ΔCVaR₀.₀₅(C_min)/|EΠ|.
- Четыре варианта × 3 сида (всего **10,3 млн шагов PPO**, ≥ 1·10⁶ решений на сид в каждом варианте):

### 5.5 Вердикт гейта и узкое место

**Гейт §7.4 не пройден ни одной политикой RL ни в одном стрессе** (`rl/results/champion_a2.json`: чемпион —
`best_rule`). Кандидаты гейта — лучшие по валидации чекпойнты: 8 из 9 — это BC (= статический чемпион; ΔCVaR к
лучшему правилу ≠ 0 только там, где чемпион — CP-SAT), девятый — `L0rule_seed3` (PPO, 2 млн шагов): base
+0,0002 % [−0,0010; +0,0055], p = 0,47 — не значимо. Отрицательный контроль (финальные PPO, отвергнутые ранней
остановкой): `L0rule_p0_last` значимо **хуже** (base −0,015 % [−0,037; −0,002]; к чемпиону −0,023 % [−0,049; −0,005]),
т. е. ранняя остановка по валидации сработала как защита. Ближе всех к гейту — не RL, а статический ключ ГА:
+0,033 % [−0,0006; +0,162], p = 0,083, положителен на 7/12 экземплярах, но ΔCVaR(C_min) < 0 и ДИ содержит 0.

**Экстренное реагирование (стресс «шок», 2 400 пар, разности к лучшему правилу):** время восстановления
пропускной способности ни у кого значимо не отличается (ДИ содержат 0). Оракул «срочный первым» значимо
уменьшает потерю прибыли от шока (−0,78 млн ₽ [−1,03; −0,56] на сценарий) и выигрывает 20 % шоков; очередь
CP-SAT — просрочку от шока (−16,9 ч [−26,4; −7,3]) и потерю прибыли (−1,50 млн ₽), но ухудшает хвост кассы (§5.4).
Политики RL, принятые валидацией, повторяют чемпиона (−1,2 ч просрочки, −0,09 млн ₽ — эффект CP-SAT-чемпиона на
plan3/rnd7); отвергнутый `L0rule_p0_last` теряет от шока больше (+0,52 млн ₽ [+0,34; +0,72]).

**Узкое место — постановка (A), вторично — обучение (B).**
- (A) Перестановка правил почти не управляет ХВОСТОМ прибыли: граница «ясновидящего» ≤ 0,01 % на 5/12 экземплярах
  (rnd1, rnd2, rnd7, rnd8, rnd9), а IQM-гейт требует выигрыша на большинстве экземпляров. Хвост CVaR₀.₁(Π) задают
  сценарии, где дороже всего обходятся длительности/ремонты/поставки (затраты, а не очередность), либо где срочного
  заказа нет: срочный заказ добавляет выручку, и сценарии с ним редко попадают в худшие 10 %. Деньги от
  реактивности есть в СРЕДНЕМ (граница +0,04…+1,9 % E[Π]; оракул — значимо меньшая потеря от шока), но гейт
  измеряет хвост.
- (B) PPO не выучил даже то, что делает оракул (к своему чемпиону +0,19 % на rnd5 в V5-запасе §5.2): при сигнале порядка 10⁻⁴ E[Π]
  против экзогенного разброса ~10⁻² (а с парной CRN-наградой — при редких событиях) отклонения от чемпиона на
  валидации только вредили; макро-шаг 24 ч не сдвинул argmax вовсе.

### 5.6 Следующий эксперимент
1. **Постановка (A), главное.** Сделать хвост прибыли управляемым Стадией 1, не трогая гейт: (а) договорные структуры
   с жёсткими сроками и отказом не только для срочных заказов (сейчас базовые заказы теряют ≤ 20 % через штраф);
   (б) экземпляры, где мощность — узкое место всего портфеля на горизонте (тогда опоздание сдвигает выручку за горизонт);
   (в) совместить L0 с открытыми теперь структурными ходами L2 (outsource/reroute/reassign: они меняют МОЩНОСТЬ
   в хвостовых сценариях, чего перестановка правил не может) и с крючком `invest` (A3).
2. **Обучение (B).** Действие «чемпион + срочный первым» показало, что выигрыш живёт в узких событиях; нужна политика,
   ранжирующая операции (внимание над множеством кандидатов, A4 §3), а не выбирающая правило на всё станочное
   событие, и обучение с CVaR-весами по пакету CRN (Tamar 2015) на 10⁷ решений.
3. Предрегистрировать новый набор (≥ 30 экземпляров по §10.2а п.1) ДО обучения, чтобы итерации постановки не
   «подгоняли» гейт.
