# MENTAT — объяснение решений по графу расчёта (блок [8])

MENTAT отвечает на «почему так» по **уже выполненному** расчёту PESCADITO. Модель — локальная LLM владельца;
она подключается отдельно (решение владельца, PLAN-V2 §7). Эта волна (L) — промпты, логика работы с моделью
и интерфейс вопрос/ответ. **В продукте нет ни одного имитированного ответа**: пока модель не подключена,
панель честно говорит «Локальная модель не подключена» и показывает точный запрос («Показать промпт»).

Методическая основа — METHODOLOGY-V2 §9: модель получает **только** (а) узлы графа расчёта со значениями и
статусами паспорта, (б) двойственные оценки и вклады, (в) разности между прогонами; каждое утверждение
ссылается на узел; каждое число сверяется с узлом автоматически; модель не прогнозирует, не оптимизирует и не
оценивает параметры ([Turpin23], [WP167] в docs/research/C1-corpus.md §9).

## 1. Архитектура

```
DecisionContext + ответы API ──► context/ ──► prompts/ ──► POST /api/mentat/ask ──► локальная LLM
 (сценарий, портфель, план,      граф вокруг   system +       (backend/src/Mentat*.cpp:     (OpenAI-совм.
  касса, RL, инвестпроект,       узла вопроса,  примеры +      проверка адреса и тела,       или Ollama)
  прогон сравнения)              бюджет        задание +      аудит, 503 без модели)            │
                                 токенов       контекст +                                       ▼
                                               вопрос                                  текст ответа
   UI: ответ по утверждениям ◄── verify/ (каждое число ↔ значение процитированного узла) ◄──────┘
       ✓ / ⚠ / ✕ + чипы ссылок → #/map/<узел>
```

| Слой | Файлы | Что делает |
|---|---|---|
| Контекст | `src/features/explain/context/{buildContext,facts,diff,budget,serialize,values,anchor,types}.ts` | Узлы пути объяснения (`explainPath`: против рёбер от результата к входам), формулы и параметры подблоков пути, факты (вклады изделий, двойственные цены мощности и ликвидности, гейт и ходы RL, CRN-оценка инвестпроекта, режим макро-генератора), разности прогонов `diff.*`. У каждого узла — id, подпись, род, статус паспорта, значения **текстом** по `src/explain/format.ts`, расстояние до узла вопроса. Усечение по бюджету детерминировано: расстояние → род узла → id |
| Промпты | `src/features/explain/prompts/{system,templates,fewshot,build}.ts` | Системный промпт (версия `mentat-sys/1.0.0`), 11 шаблонов задач + «свой вопрос», 2 примера few-shot, сборка сообщений и текст для «Показать промпт» |
| Проверка | `src/features/explain/verify/{numbers,claims,verify}.ts` | Разбор чисел русского формата, разбиение на утверждения, вердикт по каждому |
| Клиент | `src/features/explain/llm/{settings,mentatApi,history}.ts` | Настройки модели, вызовы MENTAT-API (с кодом ответа: 503 = не подключена), история по проекту |
| UI | `src/features/explain/{MentatPanel,AskTab,AnswerView,PromptTab,HistoryTab,SettingsTab}.tsx`, `useMentat.ts`, `mentat.css` | Панель: «Вопрос», «Промпт», «История», «Подключение» |
| Сервер | `backend/src/{Mentat.h,Mentat.cpp,MentatRoutes.cpp}`, `backend/tests/test_mentat.cpp` | `/api/mentat/status`, `/api/mentat/settings`, `/api/mentat/ask` |

Точки входа в панель: кнопка MENTAT в верхней панели, **Cmd/Ctrl+J** (Esc — закрыть), командная палитра,
«Спросить MENTAT» в панели узла карты и «Спросить MENTAT: почему так →» в каждом «i» показателя (узел вопроса =
этот узел). На ширине ≥ 1280 px панель пристыкована: ссылка ответа открывает узел карты рядом с панелью.

## 2. Контекст

Формат (`mentat-ctx/1`) — то, что модель видит в блоке КОНТЕКСТ:

```json
{ "version": "mentat-ctx/1", "asked": "crit.profit.f.cvar",
  "scope": { "scenarioName": "Базовый", "portfolioRunId": "…", "computedAt": "…" },
  "nodes": [ { "id": "crit.profit.f.cvar", "title": "CVaR прибыли", "kind": "formula", "d": 0,
               "status": "расчёт", "formula": "opt.cvar",
               "values": { "CVaR прибыли": "−53,7 млн ₽", "Уровень хвоста α": "10 %", "Число сценариев N": "3 000" } }, … ],
  "edges": [ ["dec.portfolio", "crit.profit", "data", "…"], … ] }
```

- Сырые числа в промпт не попадают — только текст форматтеров; сырые значения остаются в объекте контекста
  для проверки.
- Факты: `crit.profit.risk_contrib` (доли изделий в **дисперсии** прибыли, cov(Πₛ, Π)/var(Π) — не разложение
  CVaR), `dec.portfolio.duals`, `dec.cash.duals`, `ag.rl.gate`, `ag.rl.move.N`, `dec.invest.base`,
  `dec.invest.cand.N`, `ext.regimes.run`; разности `diff.runs`, `diff.opt.<метрика>` (текущий − сравнение,
  считает код).
- Бюджет по умолчанию 3 000 токенов (оценка — 3 символа на токен, консервативно для кириллицы); 15 % (≤ 400)
  — под рёбра. Не вошедшие узлы помечаются в промпте (`truncated`).

## 3. Каталог промптов

| id | Версия | Чип | Узел вопроса | Нужен расчёт |
|---|---|---|---|---|
| — | `mentat-sys/1.0.0` | системный промпт | — | — |
| `why_decision` | 1.0 | Почему это решение | `dec.portfolio` | портфель |
| `cvar_driver` | 1.0 | Что определило CVaR | `crit.profit.f.cvar` | портфель |
| `compare_runs` | 1.0 | Сравни два прогона | `crit.profit` (+ `diff.*`) | портфель + прогон сравнения |
| `bottleneck` | 1.0 | Почему такое узкое место | `dec.schedule.f.bottleneck` | план |
| `agent_move` | 1.0 | Объясни ход агента | `ag.rl` (+ `ag.rl.move.N`) | план с ходами |
| `invest_payback` | 1.0 | Окупится ли инвестпроект | `dec.invest` | инвестпроект |
| `crisis` | 1.0 | Что при кризисном режиме | `ext.regimes` (+ `ext.regimes.run`) | портфель; **только посчитанный стресс** |
| `param_origin` | 1.0 | Откуда параметр | выделенный узел / `crit.profit.alpha` | — |
| `rl_gate` | 1.0 | Почему RL не прошёл гейт | `ag.rl` (+ `ag.rl.gate`) | статус RL |
| `cash_risk` | 1.0 | Как снизить риск разрыва | `crit.cash.f.p_breach` | касса; **только рычаги из графа** |
| `makespan` | 1.0 | Почему такой E[Cmax] | `dec.schedule.f.makespan` | план |
| `custom` | 1.0 | Свой вопрос | выделенный узел | — |

Версия запроса — `mentat-sys/1.0.0+<шаблон>@<версия>+mentat-ctx/1`; пишется в аудит и в историю.
Правка текста системного промпта или шаблона = новая версия.

Правила системного промпта (кратко): только КОНТЕКСТ; ссылка `⟦node:<id>⟧` после каждого утверждения;
числа дословно из `values` процитированного узла, без пересчёта; связи — только по рёбрам; запрет прогнозов,
оптимизации, оценки параметров и советов вне рычагов графа; неопределённость — по статусу паспорта (Н, О, К,
НОРМ, UI, техн., синтетика, по умолчанию, вручную, расчёт, нет прогона, в плане, рассчитано; К и НОРМ никогда
не «оценено»); без ДИ — не утверждать значимость; структура «Вывод → Почему → Что проверить», до 180 слов;
отказ — фраза «в контексте нет данных» и узел, который нужно рассчитать.

Примеры few-shot (`fewshot.ts`) — настоящая форма графа, но вымышленные значения; в запросе помечены «ПРИМЕР
ФОРМАТА — значения вымышлены», пользователю как ответ не показываются; их ответы проходят ту же проверку
верности (тест). Отключаются в «Подключении» для малых окон контекста (≈ 1,5 тыс. токенов экономии).

## 4. Проверка верности

- Ответ режется на утверждения (строки → предложения; маркеры списков и разметка снимаются; ссылки, стоящие
  после точки, относятся к предыдущему утверждению).
- Числа разбираются в формате интерфейса: «1 263 ч», «−53,3 млн ₽», «1,85 тыс. ₽», «10 %», «16,5 п. п.»,
  «[+1,01; +1,92] %»; обозначения вида «16К20» числами не считаются.
- Число сверяется **только** со значениями узлов, процитированных в том же утверждении, с допуском половины
  последнего показанного разряда (`−53,3 млн` ↔ −53 312 000 ✓, `−53,4 млн` ✗); проценты — с долями (`%`) и с
  процентными пунктами (`%/год`, `% стоимости портфеля`); число без знака может совпасть по модулю (помечается).
- Вердикты: ✓ сверено (все числа совпали), ✓ со ссылкой (утверждение без чисел), ⚠ число не совпало,
  ✕ нет ссылки (число без узла), ✕ неизвестный узел (id вне контекста); фразы без чисел и ссылок — нейтральные.
  Ответ «проходит», если нет ни ⚠, ни ✕.

## 5. Как подключить локальную модель

Достаточно адреса и имени модели — через «MENTAT → Подключение» (сохраняется в настройках проекта, ключ
`app_prefs.mentat.llm`, право EDIT_NSI) или переменными окружения сервера (имеют приоритет):

| Переменная | Смысл |
|---|---|
| `MAOS_LLM_URL` | адрес сервера модели; задан — адрес из настроек проекта не используется |
| `MAOS_LLM_MODEL` | имя модели (иначе — из настроек проекта) |
| `MAOS_LLM_FLAVOUR` | `openai` (по умолчанию) или `ollama` |
| `MAOS_LLM_API_KEY` | ключ, если сервер модели его требует (только окружение; не хранится и не логируется) |
| `MAOS_LLM_ALLOWED_HOSTS` | нелокальные хосты, которым разрешено отдавать запросы (через запятую) |

**Ollama**

```bash
ollama serve                       # слушает 127.0.0.1:11434
ollama pull qwen2.5:14b-instruct   # любая инструктивная модель с русским
MAOS_LLM_URL=http://127.0.0.1:11434 MAOS_LLM_FLAVOUR=ollama MAOS_LLM_MODEL=qwen2.5:14b-instruct ./maos_server maos.db
```
Запрос: `POST /api/chat` с `{model, messages, stream:false, options:{temperature, num_predict}}`.

**OpenAI-совместимый сервер (vLLM, llama.cpp `llama-server`, LM Studio)**

```bash
vllm serve Qwen/Qwen2.5-14B-Instruct --host 127.0.0.1 --port 8000
MAOS_LLM_URL=http://127.0.0.1:8000/v1 MAOS_LLM_MODEL=Qwen/Qwen2.5-14B-Instruct ./maos_server maos.db
```
Запрос: `POST <адрес>/chat/completions` (если адрес оканчивается на `/v1`, иначе `/v1/chat/completions`) с
`{model, messages, stream:false, temperature, max_tokens}`.

После запуска — «Подключение → Проверить соединение» (`GET /api/mentat/status?probe=1`: `/v1/models` или
`/api/tags`, таймаут 5 с, список моделей и предупреждение, если указанной модели на сервере нет).
Рекомендуемые настройки: температура 0,1; 800 токенов ответа; таймаут 120 с; бюджет контекста 3 000
(при окне модели 8 тыс. — без примеров few-shot или бюджет 2 000).

## 6. API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/mentat/status[?probe=1]` | `{configured, source: env\|prefs\|null, base_url, model, flavour, reachable, error, models, settings, env_locked}` |
| PUT | `/api/mentat/settings` | тело — настройки (нормализуются: температура 0…1, токены 64…4096, таймаут 5…600 с, контекст 500…12 000); 400 — адрес не разрешён |
| POST | `/api/mentat/ask` | тело `{messages, template_id, prompt_version, asked, context:{nodes, tokens}}` → 200 `{text, model, flavour, ms, prompt_version}`; **503 `LLM не подключена`**; 400 — тело не прошло проверку; 413 — больше 512 КиБ; 502 — модель не ответила / ответ без текста |

Права: `ask` — любой вошедший (READ), `settings` — EDIT_NSI. Фронтенд не шлёт `ask`, если статус уже говорит
«не подключена».

## 7. Безопасность

- Адрес модели: только `http://` (TLS, если нужен, — обратным прокси вне MAOS), без логина/пароля, без query и
  якоря; хост — `localhost`, `*.localhost`, `127.0.0.0/8`, `::1` или явно перечисленный в
  `MAOS_LLM_ALLOWED_HOSTS` (плюс хост самой `MAOS_LLM_URL`). Проверяется при сохранении и при каждом запросе —
  настройки проекта не могут превратить сервер в прокси на произвольный адрес (SSRF).
- Без перенаправлений (`follow_location = false`), таймаут соединения 3 с, ответа — из настроек; ответ модели
  > 2 МиБ отбрасывается.
- Тело `ask`: ≤ 512 КиБ, 1…16 сообщений, роли `system|user|assistant`, каждое ≤ 160 КиБ, последнее — `user`.
- Ключ — только переменная окружения; в ответы статуса, аудит и журналы не попадает.
- Аудит: на каждый вопрос запись `actions(entity_type='mentat', action_type='ASK'|'ASK_FAILED')` — шаблон,
  версия промпта, узел, текст вопроса (≤ 500 символов), число узлов и токенов контекста, модель, код, время;
  **текст ответа — только при включённом «Писать текст ответа в журнал аудита»** (по умолчанию выключено).
  Изменение настроек — `UPDATE settings`.
- История ответов хранится в браузере этой машины (localStorage, ключ по проекту-БД), до 50 записей.

## 8. Что отложено

- Подключение и выбор конкретной модели — владелец; оценка качества объяснений (доля сверенных утверждений,
  доля отказов «нет данных» при отсутствии расчёта, слепая экспертная оценка) — после подключения (THESIS-FINDINGS
  В7 — запланировано).
- Потоковая выдача ответа (сейчас `stream:false`, ответ целиком).
- Контрфактическая проверка утверждений «если бы…» повторным запуском симулятора ([Wachter18]) — отдельная волна.
- Серверный `GET /api/method-map/state` (контекст сейчас собирает фронтенд по тем же ответам API).
- Точный подсчёт токенов токенизатором модели (сейчас консервативная оценка по длине).
